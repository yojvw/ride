## 一句话定位（开场必须统一）

> 我们分析了一座城市一个月的共享单车骑行数据，回答两个问题：**车都去哪了，该往哪调。**

三个人在任何场合都不要说"我们的目的是做一个预测模型"——
建模是手段，落点是**调度建议**。

统一表述模板（被问到差异时三个人都这么答）：

> 三人独立做完以后我们做过交叉验证，原始规模、站点数、峰值时段、潮汐方向**完全一致**；
> 样本量的差异全部来自时长阈值的设定不同，**逐层相减可以精确闭合**，
> 所以主要结论对清洗阈值不敏感，是稳健的。

## 四、三条建议（收尾三人可用同一版措辞）

1. **按潮汐调度**：早高峰前向居住区站点补车，晚高峰前向市中心站点清车，作业要前置到高峰开始前。
2. **锁定 20 个重点站**：净流出 TOP20 每日固定巡检，其余按需响应；对失衡指数 >25% 的小站单独设优先级。
3. **分人群运营**：工作日主打会员通勤权益，周末向临时用户推休闲路线与时长套餐。

收尾一句话：**"数据告诉我们车该往哪去，剩下的是执行频率的问题。"**

## 五、问答 3 分钟高频题（统一答复口径）

| 可能被问 | 统一答复 |
|---|---|
| 为什么不用 dropna 删缺失？ | 那 37,220 条 100% 是电单车，可站点外还车，是业务差异不是脏数据；删掉会抹掉一整类用户行为。 |
| 为什么按时间切分而不是随机切分？ | 时序数据随机切会让测试集与训练集时间相邻，模型靠"记邻近时刻"刷高分，是信息泄漏。 |
| 失衡指数为什么设 100 次门槛？ | 只影响排名展示，避免低频站随机波动干扰；761 个站全部保留在结果表里，438 个参与排名。 |
| R² 只有 0.34，模型是不是没用？ | 我们的结论恰恰是**需求可预测性主要来自时段规律与站点历史水平**，复杂模型边际收益只有 1.39%，工程上用简单方案更划算。 |
| 为什么不用 XGBoost？ | 本机环境未安装；而且线性回归与随机森林差距已说明复杂模型增益有限，换模型不改变结论。 |
| 调度建议怎么落地、成本怎么估？ | 月度搬移规模下界 6,916 辆次可作为车辆与人力配置的量级参考；精确排线需要接入路网与调度车容量，属于下一步工作。 |
