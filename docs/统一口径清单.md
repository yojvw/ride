# 统一口径清单（三人代码若要对齐，须同时满足以下 5 条）

> 背景：三人各自独立完成全流程，清洗阈值不同导致行数不同（238,699 / 233,749 / 233,180）。
> 若要把三份代码"合一"或让三人的数字完全对齐，**仅统一清洗阈值是不够的**。

---

## 一、必须统一的 5 条口径

### 1. 骑行时长有效区间

| 成员 | 当前阈值 | 结果行数 |
|---|---|---|
| 杨佳伟（定稿） | 1 ~ 1440 分钟 | 233,749 |
| 张熙正 | 1 ~ 180 分钟 | 233,180 |
| 尹泽宇 | 仅剔除时长 ≤ 0 | 238,699 |

统一值：**`duration_min >= 1 且 <= 1440`**，另剔除 `end_lat / end_lng` 缺失的记录。

### 2. 站点缺失的填充方式

统一值：起点/终点站名与站号 4 个字段，**一律 `fillna("站点外停车")`**，禁止 `dropna()`。

原因：缺失的 37,220 条 100% 是 electric_bike，属结构性缺失。

### 3. 流入 / 流出的时间归属（最容易错，会改变符号）

统一值：

- **流出（借车）** 按 `started_at` 的小时计；
- **流入（还车）** 按 `ended_at` 的小时计，包含跨日到达。

反例：若流入也按出发时间计，枢纽站的净流量符号会翻转。
实测 Columbus Circle / Union Station：定稿口径 **−49**，另一口径 **+41**。

### 4. 站点集合的定义

统一值：**起点站名 ∪ 终点站名**（排除"站点外停车"后）= **761 个**。

只算起点会得到 759，排名随之变化。低频站点是否入榜另设门槛：进出总量 ≥ 100 次（761 个中 438 个满足），但不参与排名的站点仍须保留在结果表中。

### 5. 建模的切分与随机种子

统一值：

- 训练 1/1–1/24，测试 1/25–1/31（**按时间切分，禁止随机切分**）；
- `random_state = 42`；
- `hist_mean` 只用训练集计算后冻结，测试期不得重算；
- 样本网格 = TOP50 站点 × 31 天 × 24 小时 = 37,200 行（无骑行的小时记 0，不得只保留有骑行的组合）。

## 二、验证方法（统一之后必须跑）

三人各跑一遍自己的脚本，逐项比对以下 8 个数字，**完全一致才算真正对齐**：

| 检验项 | 期望值 |
|---|---|
| 清洗后行数 | 233,749 |
| 时长中位数 | 8.92 分钟 |
| 会员 / 临时 | 173,286 / 60,463 |
| 站点总数 | 761 |
| 峰值小时 | 17 时，23,392 次 |
| 净流出 TOP1 | Adams Mill & Columbia Rd NW，−338 |
| 全市 \|net\| 合计 | 13,832 |
| 随机森林 RMSE | 2.2215 |

任一不一致 → 一定是上面 5 条中还有没对齐的，**不要靠"差不多"糊过去**。

## 三、是否要合并代码：结论与替代方案

**不建议合并为一套。** 理由：

1. 课程要求"成员分工与个人承担所写的各人负责模块应能与提交记录对应"——三套过程稿各自留痕正好满足，合成一套反而对不上；
2. "三人独立复现 + 差异可解释"是本项目相对其他组的独有优势，合并后消失；
3. 当前时间节点（10/31 交视频与 PPT）下，合并的收益远低于成本。

**替代方案（推荐）：** 张熙正、尹泽宇各自在 `src/member_b/`、`src/member_c/` 下追加一份**按本清单口径重跑**的版本，跑通后：

- 三人数字完全一致 → 报告第 8.3 节可升级为"**统一口径下三人结果完全一致，且各口径下主要结论保持一致**"；
- 成本：每人约十分钟，只需改阈值与时间归属两处。

目录保持不变：

```
src/step0~step5.py      定稿（报告与汇报引用的正式版本）
src/member_a/           杨佳伟过程稿
src/member_b/           张熙正过程稿 + 定稿口径复跑版
src/member_c/           尹泽宇过程稿 + 定稿口径复跑版
```
