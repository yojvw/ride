# 先读我：共享单车算法增量优化 v0.2.0

这次只交付一个ZIP。它是原v0.1.0项目的增量插件，不是替代整个项目的全量包。

## 1. 本次做了什么

根据GPT_HANDOFF.md与OUTPUT_REPORT.md描述的基线，增加近期水平特征、MAE导向候选、时间加权与固定融合；增加严格的验证/测试分离、同样本比较、配对日块bootstrap、实验台账及方案锁定。

没有修改清洗数据，没有覆盖原bikeproject/io.py、原tests/、原forecast.py、原run.py及results/real_run_01。调度模拟不在本轮改动范围；不会把一个MAE最优的中位数预测自动冒充期望需求送进调度。

目前只收到两份Markdown报告，没有实际CSV、最新源码或逐条预测文件。故本包完成的是算法实现和虚构数据验证，不是已经取得真实MAE下降的最终实验。不能把虚构演示的提升当成课程数据结果。

## 3. 第一次只跑验证，不跑测试

```powershell
.venv\Scripts\python.exe optimize_bike.py tune --config configs\optimization_v020.json
```

默认实验目录是experiments/opt_v020_001。已有同名目录会拒绝覆盖；若确有新的、预先计划的实验，修改配置run_id并保留旧台账，不随意删除旧目录。

它会依次：

1. 调用原io.py验收真实输入，调用原panel.py选站与建表。
2. 检查三份输入SHA256与交接报告完全一致。
3. 固定训练/验证/测试日期、站点口径及原full特征样本掩码。
4. 从构造优化特征前就截断到验证期结束，不在tune输出测试指标。
5. 比较6个预先固定候选，并做两折滚动CV。
6. 与旧predictions.csv的验证期hgb_full逐样本比较，最大预测差异须≤1e-9。
7. 如果基线无法复现，拒绝发布锁定方案；不要通过放宽校验“通过”。
8. 按验证结果和预设约束选方案，不达标则保留原模型。
9. 输出LOCK.json及其校验摘要，冻结数据、代码、环境、参数和候选。

注意：输入加载会读取原始文件用于原校验与构建面板，文件哈希也覆盖整个输入文件；“验证阶段不看测试”指不使用测试目标来训练、挑选或评分，不是声称CSV后半段从未被读取到内存。

默认筛选要求：验证MAE下降，配对区间上界<0，滚动CV总体MAE相对原模型不恶化超过2%，验证峰值MAE及峰值欠预测率不恶化。2%是可事先设定的工程容忍度，不是“统计噪声定律”。

所有候选都是在同一验证集比较，bootstrap区间没有做选择后推断或多重检验校正；只能作为保守筛选的描述性依据，不能宣称严格显著性已经被证明。

如果两个目标都保留hgb_full，代表目前没有足够验证证据支持换模型。不要为了“优化成功”而删除基线或不断放宽门槛，也不必再消耗测试预算。

## 5. 确认方案后，才进行最终复核

只在查看验证报告、认可锁定方案后运行：

```powershell
.venv\Scripts\python.exe optimize_bike.py finalize --run experiments\opt_v020_001 --acknowledge-used-test
```

这个命令明确承认：此前已看过测试期报告，本次不是未见过的盲测。

它会检查数据、代码、环境、配置未发生改变；按已锁定候选，在1月25日之前的数据上重训，再评估1月25日至2月1日。只比较锁定方案与原hgb_full，不在测试集再跑全部候选挑赢家。

测试预算默认历史已用1次、最多累计3次。本工具维护本地预算和实验台账；它无法追踪其他脚本手动运行的测试，若此前实际用过更多次，应在第一次运行前如实调整。预算不让已被研究过的测试集重新变独立。

每个run只允许一次finalize。预留后即使运行失败也消耗预算，以避免偷偷反复试；应先排除环境和数据问题。不要删除预算文件来绕过约束。

## 6. 六个候选

| 名称 | 相比上一层改变什么 |
|---|---|
| hgb_full | 原模型，由原forecast.py拟合，保留完整基线 |
| adaptive_poisson | 同一Poisson模型参数，增加近期水平/相对强度特征 |
| adaptive_mae | 同一新增特征，损失改为absolute_error，与MAE目标更一致 |
| adaptive_recent | 同一新增特征与Poisson损失，训练样本按72小时半衰期加权 |
| adaptive_longer | 同一新增特征与Poisson参数，仅把max_iter从原80改为160 |
| blend_mean_median | 固定0.5×adaptive_poisson + 0.5×adaptive_mae；不在测试调融合权重 |

基线默认参数继承原配置；并不是把原模型重新实现成另一个“近似基线”。adaptive各候选则按原80次/15叶/叶最小15/L2=1/学习率0.1的标准参数构造，仅改变声明的部分。原模型参数若与交接版本不同，应审核源码后再运行，不要默认为兼容。

新增19个数值特征：星期×小时，借还分别的24/72小时指数均值、过去168小时均值、过去7个同钟点均值、近期/日均强度比、昨天同小时与日均差、两种指数均值差、上一小时与昨天同小时差、过去24小时零值比例。

不加入未来气象、目标小时会员数量、假库存或推定缺车量；不对预测强行四舍五入或把小数硬截成0。

## 7. 重要纠正与限制

- 原列举的历史特征每目标是8个而非9个，因此原v0.1代码的数值特征为7+8+8=23，不是25。插件会检查真实源码的列集合；若不一致停止，要求审核。
- 向后看的shift(1).rolling(168)需要168小时暖启动，不是336小时；旧lag_168已经支付这个成本。新增特征不改变原资格掩码；额外缺失由HGB原生NaN机制处理，不填目标值。
- HGB没有tweedie损失选项，不能照交接文档的伪代码直接调用。TweedieRegressor是另一种模型，不等价于HGB。
- Poisson均值预测为正很正常。约30%观测为0本身不足以证明零膨胀；本版用MAE损失和历史零值比例作为可检验候选，不以未证实的诊断强行加入零分类器。
- 按真实高值筛选的峰值样本本来就容易被均值回归低估；85%欠预测率不能单独证明存在可纠正的系统偏差。应结合日历时段误差、总体偏差和验证结果。
- MAE最优通常对应条件中位数；调度可能更需要期望需求/上分位，不能因MAE改善就宣称调度收益改善。
- 单月/6天验证/7天测试和多个候选都限制推断；不存在普适的“提升不到2%就是噪声”。
- 已知旧测试结果影响了优化方向，后续该测试期只能做探索性复核；若要严格独立结论需要新的未使用时间段。
- 沿用旧coverage假设。原coverage由全月活动回溯推定，可能含回溯偏差；新增算法不会把它升级成confirmed或修复真实未观测需求。
- 未加天气/假日外部数据、未实现conformal、自动时序早停、在线部署或真实库存优化，不作这些功能的承诺。

## 8. 如果报错

| 报错 | 正确处理 |
|---|---|
| 找不到bikeproject | 新文件没与原run.py同级，或工作目录错误 |
| pandas类型校验失败 | 使用原已验证.venv，不修改io.py断言 |
| Input digest mismatch | 实际数据与交接版本不一致；先核查，不删除哈希检查 |
| 原始特征集合不一致 | 当前源码可能已改动；提供实际源码和特征表审计 |
| baseline predictions not reproduced | 对比环境、原配置、原CSV与原预测明细；不要删掉复现检查 |
| 样本数不符 | 检查站点口径、覆盖和分割日期，不靠丢样本“提高精度” |
| LOCK发生改变 | 方案冻结后代码或配置变了，不能继续当同一次实验测试 |
| 测试预算耗尽 | 停止用这段测试调参，考虑新未使用数据 |
