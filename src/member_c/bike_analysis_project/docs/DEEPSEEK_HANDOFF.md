# 给DeepSeek的交接文档：共享单车题目五数据清洗

版本：v0.1.0；交接日期：2026-10-29。

## 1. 你的任务与边界

你负责原始骑行CSV的数据审计、字段标准化、可追溯清洗和输入数据交付。下游Python项目已实现小时面板、时空分析、借还预测、时间验证、调度方案与情景回放。

不要替下游提前训练模型、随机划分数据、构造全月历史均值或推测真实库存。当前项目没有接触老师的实际骑行CSV，字段映射必须根据真实文件确定，不要把示例字段误当成真实字段。

建议先回复：实际列名、数据行数、时间范围、各列缺失率、订单ID是否可靠、站点字段是否稳定。确认后再清洗。不要声称零订单时间段已被证实数据完整。

## 2. 交付目录

```text
data/clean/
  rides.csv                 必需：有效时间订单，保留有用的站点缺失记录
  coverage.csv              必需：站点可用覆盖区间，必须标明证实或假设
  stations.csv              推荐：稳定站点坐标；空间图/调度需要
  rejected_rows.csv         从分析输入排除的原记录及原因
  cleaning_report.json      清洗统计，规则、重叠数量及最终保留数
  data_dictionary.md        字段含义、原始映射、单位、时区说明
  station_coordinate_log.csv  坐标来源/一致性/修订依据（如有）
scripts/
  clean_data.py             可重复执行的清洗程序
```

CSV为UTF-8或UTF-8-SIG，英文列名，小数点使用`.`。保留原始CSV不覆盖。不得在未知情况下改写为其他城市/时区。

## 3. rides.csv精确接口

必需列：

| 列名 | 类型 | 规则 |
|---|---|---|
| ride_id | 字符串 | 非空、唯一。无原始ID时根据源文件+原行号生成稳定ID；生成ID不能作为没有重复订单的证据 |
| started_at | 日期时间字符串 | 示例2024-01-08 08:50:00；同一数据当地时钟，暂不附时区偏移 |
| ended_at | 日期时间字符串 | 必须晚于started_at；跨日订单允许 |
| start_station_id | 字符串或空 | 保留前导零；无站点不能随便用坐标猜ID |
| end_station_id | 字符串或空 | 同上 |
| member_type | 字符串 | 优先映射为member/casual/unknown；不确定保留可解释原类别 |
| bike_type | 字符串 | 如classic/electric/unknown；不捏造车型 |

建议保留列：

| 列名 | 规则 |
|---|---|
| duration_min | 由结束减开始计算的分钟数；不与真实值相差超过0.02分钟 |
| start_lat / start_lng | 数值或空；纬度[-90,90]、经度[-180,180]；合法范围不等于城市内真实坐标 |
| end_lat / end_lng | 同上 |
| quality_flags | 问题标志，如missing_start_station、long_duration_reviewed；无问题可为空 |
| source_file / source_row | 原始来源追溯信息 |
| start_station_name / end_station_name | 可保留，但下游按ID连接，不按名称猜测 |

附加列可保留，下游不会自动作为预测特征使用。

接口的虚构示例：

```csv
ride_id,started_at,ended_at,start_station_id,end_station_id,member_type,bike_type,duration_min,quality_flags
example_001,2024-01-08 08:50:00,2024-01-08 09:10:00,001,002,member,classic,20,
example_002,2024-01-08 09:00:00,2024-01-08 09:15:00,,002,casual,electric,15,missing_start_station
```

这两行仅说明格式，不能掺入真实数据。

## 4. 清洗规则

1. 时间不能解析或结束不晚于开始：输出到rejected_rows.csv，记录明确原因，不进入rides.csv。
2. 时长过长：先展示分位数、分布和原记录。不要机械删去所有超过30/60分钟的骑行。若使用数据驱动阈值影响建模样本，应仅用训练期拟合规则，或交由下游处理；不要在完整测试期上挑有利阈值。
3. 同起终点：不是错误，除非有额外证据。
4. 缺站点：时间完整的订单保留；能统计总时间规律，端点有效时还能统计该端点流量。
5. 缺坐标：不可填0；无法修复时留空。不能因坐标缺失就删除时间和站点均有效的订单。
6. 重复ID：完全重复可按预先规则去重。相同ID内容冲突必须单独记录并说明保留依据；不允许仅换ID掩盖冲突。
7. 同时同路线但不同有效ID：不能直接当成重复订单。
8. 站点ID必须按字符串读取和保存。不要先转浮点再转字符串，避免001变成1或1.0。
9. 用户/车型缺失用unknown并统计，不按猜测补会员身份或车型。
10. 原始月份边界订单可保留。跨1月31日至2月1日的骑行不能仅因到达在2月就判为错误；下游分别按借出和归还时间筛选窗口。
11. 记录每条规则单独命中数、与其他规则重叠数、最终排除数，不把多个命中计数相加当成去重后删除量。
12. 不“修平”早晚高峰，不把较大的真实流量当离群值删除。

## 5. coverage.csv：最容易误交接的表

这是站点数据可用区间，不是“站点有订单的区间”。它决定无记录小时能否填0。

```csv
station_id,start,end,status
001,2024-01-01 00:00:00,2024-02-01 00:00:00,assumed
002,2024-01-01 00:00:00,2024-01-15 00:00:00,confirmed
002,2024-01-16 00:00:00,2024-02-01 00:00:00,confirmed
```

- 区间为左闭右开[start,end)，必须整点对齐。
- 同一站点的区间可多行，但不能重叠。
- 第二个站点1月15日全天没有覆盖，下游保留缺失，不填0。
- confirmed：有独立依据说明该区间站点运营与订单记录覆盖完整；必须在报告写依据。仅“每天都有订单”不足以证实完整。
- assumed：只能基于假设认为覆盖完整。没有运营日志或平台说明时，宁可标assumed，不得编造confirmed。
- 下游默认拒绝assumed。项目负责人审阅后可显式设置allow_assumed_coverage=true，报告必须披露该假设。
- 不建议简单用第一笔至最后一笔订单当真实开闭站日期。若只能如此推定，必须标注为假设，并讨论边界偏差。
- 如果覆盖未知到无法提出合理假设，请停止补零，交付数据审计结论，由负责人决定缩小分析范围。

## 6. stations.csv

```csv
station_id,lat,lng
001,40.70,-73.99
002,40.71,-73.98
```

上面坐标仅是格式示例，不代表真实站点。每个站点一行，ID唯一。

优先采用官方静态站点资料。若从订单推定坐标，请检查同站点是否迁移、坐标是否分散，并记录来源。为保证预测/决策复现，优先使用训练前已知资料或训练早期记录，不用测试期信息重构“过去已知的站点位置”。无法可靠确认时留空，不伪造。

下游允许不提供stations.csv：配置stations_path=null即可运行非空间部分；空间图会跳过，调度回放须关闭。不要把真实未知容量填进此表当成观测值；当前回放容量统一由情景配置给定。

## 7. 时间口径

必须写清城市/数据源采用的时区、原始时间是否含偏移、是否存在夏令时或重复本地时间。不要使用用户所在地东京/北京时间代替数据时区。

当前版本接受一致的无时区本地时间。若实际数据有UTC偏移混杂或夏令时歧义，先报告，不要直接删除时区字符串；需调整下游设计后再接入。配置中的time_basis不能为空或保留REPLACE占位文字。

## 8. 禁止提前做的内容

- 不随机打乱后切训练/测试。
- 不用全月统计选择建模站点或填补预测特征。
- 不将目标小时实际会员订单数作为预测该小时需求的输入。
- 不把未来订单加入滚动平均，不跨站点shift。
- 不生成虚假的库存、站点容量、卡车路线、天气、节假日标签或成本。
- 不把骑行记录的净流出直接命名为真实缺车量。
- 不把合成示例或模型预测补成真实订单。

## 10. 验收与接入

- [ ] 原始数据未覆盖；清洗脚本可重新执行。
- [ ] 必需字段齐全，订单ID唯一，时间解析正确，时长一致。
- [ ] 缺站点、缺坐标、缺类别分别处理，没有一刀切丢弃。
- [ ] coverage的confirmed有证据，assumed如实标明，区间不重叠。
- [ ] 站点ID前导零保留；stations表ID唯一。
- [ ] 时间范围、时区、删除规则、未解决问题均有说明。
- [ ] 没有生成库存或伪造清洗结果。

把文件放入项目data/clean，负责人编辑configs/real_template.json。该配置默认关闭模拟。先执行测试，再执行真实分析：

```bash
python -m unittest discover -s tests -v
python run.py --config configs/real_template.json
```

若错误是“Assumed coverage requires explicit ...”，不要改数据为confirmed绕过检查。应由负责人审阅假设并显式修改配置。

若提示时区占位未修改、覆盖重叠、时长不一致或重复ID，应修复对应输入，不要删除校验代码。

## 11. 给DeepSeek的执行指令

请先读取原始CSV并给出字段映射和质量审计。然后按本文生成rides.csv、coverage.csv、可用时生成stations.csv，以及清洗脚本、报告、字典和排除记录。发现无法确认的覆盖、时间或站点信息时，如实写入未解决问题，不编造答案。完成后逐项说明接口验收情况，并告知哪些覆盖区间仅为假设。不要修改下游预测、测试和模拟代码来规避数据质量检查。
