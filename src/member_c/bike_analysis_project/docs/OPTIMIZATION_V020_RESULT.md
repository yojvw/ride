同一个候选在一折大胜、另一折大败，说明它学到的是这两天的局部结构，而不是可迁移的规律。这也是 `cv_ok` 门槛存在的意义。

## 5. 为什么“加特征 + 换损失”没有赢

1. **样本太少**：训练期每站 264 行、合计 5,280 行；新增 19 个数值特征后，特征数从 23 升到 42，信噪比进一步恶化。`adaptive_poisson` 在两个目标上都比原模型差约 0.7%（验证：借出 −0.66%、归还 −0.71%），是“特征噪声”的直接证据。
2. **MAE 损失趋中位数**：`adaptive_mae` 与融合模型把平均误差压低了不到 1%，代价是峰值预测被削平（峰值 MAE 3.41 → 4.11/3.84），对调度与容量决策是反向的。
3. **容量不是瓶颈**：`adaptive_longer`（160 次迭代）反而更差，说明问题不在拟合不足。
4. **验证集只有 6 天**：日块 bootstrap 的区间宽度 > 0.05，1% 的改善不可判定。

## 6. 没有做的事（有意为之）

- **没有运行 `finalize`**：包内说明要求“确认方案后再运行、不要擅自 finalize”；而且所选方案就是基线本身，跑测试只会把 `real_run_01` 已知的测试数字再算一遍并消耗一次预算。
- 没有改门槛、没有改时间切分、没有删除候选、没有放宽 `baseline_reproduction_tolerance`。
- 没有把新预测接进调度模拟。

## 7. 下一轮建议（开新 `run_id`，不改本次结论）

1. **先做特征子集**：从 19 个里只留 4–5 个（`mean_168`、`ewm_72`、`same_hour_mean_7d`、`zero_fraction_24`），其余作为消融；当前的证据指向“特征太多”。
2. **把树参数作为预注册候选**：`max_leaf_nodes 15 → 8`、`min_samples_leaf 15 → 30`，配合 80 次迭代，检验是否是过拟合而非特征无效。
3. **峰值导向的目标**：若下游关心峰值与缺车，主指标应改为峰值 MAE / 分位数损失，而不是总体 MAE；否则“MAE 最优”必然削峰。
4. **需要更长的验证期**：6 天验证 + 7 天测试不足以判定 1% 级别的差异；拿到 2–3 个月数据前，不建议继续在同一验证集上堆候选。
5. 若坚持外部数据（天气），必须写明来源与覆盖期，并单独做有无对照。
